# 録画の文字起こし方式の比較と選定

## 1. 前提（公式仕様の確認）

- Claude API（Messages API）の入力として公式に記載されているのは **テキスト・PDF・画像**。音声・動画は入力できない（Anthropic 公式 Files API ドキュメント「File types and content blocks」で確認、2026-11-04）
- したがって ReadyProof AI では「録画 → 音声抽出 → 文字起こし → 人が話者と内容を確認 → 選んだ発言の文字だけを Claude に送る」構成にした

## 2. 比較

| 観点 | ローカル処理（faster-whisper）【採用】 | 外部の文字起こしAPI（例：OpenAI gpt-4o-transcribe-diarize 等）【未実装】 |
|---|---|---|
| 日本語の精度 | small モデルでデモ音声（合成音声40秒）をほぼ正しく認識。ただし「指定日」→「指定費」の誤認識あり（実測） | 未検証 |
| 発言時刻 | 区間ごとの開始・終了時刻あり（実測） | 製品により異なる（未検証） |
| 話者の区別 | **なし**。人が区間ごとに話者を指定する | 話者分離付きの製品がある（未検証。AIの推測を確定扱いしない方針は同じ） |
| 費用 | API料金 0円（CPU時間を使用） | 従量課金。第三者サイトでは約 $0.006/分 の記載があるが公式価格表で未確認 |
| メモリと時間 | `docs/test_results.md` の実測値を参照 | サーバー側の負荷は小さい |
| Streamlit Community Cloud | 公式の上限は CPU 最大2コア・メモリ最大2.7GB（2024年2月時点の目安）。small モデル（約480MB）は理論上載るが**未検証**。長い録画は時間がかかる | ネットワークから呼べるため実行可能性は高い（未検証） |
| 外部送信先 | なし（アプリが動くサーバー内） | 文字起こし事業者へ音声を送信 |
| 必要なもの | `pip install faster-whisper`、初回のモデル自動ダウンロード（Hugging Face から無料） | 事業者との契約・APIキー・支払い設定（**未契約。契約は利用者の確認後**） |

## 3. 選定理由

1. 外部送信が不要で、録画の取り扱い（社外秘・個人の発言）の説明がしやすい
2. 有料契約なしで動作確認でき、デモも含めて費用0円で示せる
3. 話者分離がない弱点は、要件どおり「話者は人が確認・分類する」運用でカバーできる

## 4. 実装範囲と制限

- 対応形式：MP4 / WebM / MOV（音声のみ .m4a / .mp3 / .wav も可）。拡張子だけでなく PyAV で開いて音声トラックとコーデックを確認
- 処理前に 長さ・容量・音声の有無・処理方法・送信先・対象時間・費用見込み を表示。アップロードだけでは処理しない
- 時間範囲を指定して処理（1回の上限 15分。設定で変更可）。範囲外の発言は根拠に使えない
- 同じ録画・同じ範囲の文字起こしがあれば再利用（ファイルのハッシュ値で判定）
- 実行中はボタンを無効化して二重実行を防ぐ
- 動画本体はセッションのメモリにだけ置き、JSON には保存しない（保存後は「ファイル名と時刻」のみ）
- 外部コマンド（ffmpeg コマンド）は使わず、PyAV ライブラリで処理するため、ファイル名経由の命令実行は起こらない。一時ファイルはランダム名で作り、処理後に削除
- faster-whisper 1.2.1 の内部の音声読込は PyAV 19 と互換性がないため、アプリ側で 16kHz の数値配列に変換して渡している

## 5. 公開環境で処理が難しい場合の構成

- 公開環境（Community Cloud）では、faster-whisper をインストールしない構成（`requirements.txt`）にしている。録画は「会議ツールの文字起こし（VTT/SRT/テキスト）読込」を推奨し、ローカル文字起こしは手元PCでの実行を推奨する
- 字幕を読み込んだだけの場合、処理方法は「会議ツールの文字起こし読込」と記録され、「録画を文字起こしした」とは表示しない

# 要件定義（ReadyProof AI 第1版）

## 1. 目的
市販サービス・パッケージシステム（および自社開発・個別開発システムの受入）について、
「候補製品が自社業務に合うか」「不足をどう埋めるか」「実際に要件を満たしたか」を根拠付きで確認し、人の導入判断を支援する。

- 名称：ReadyProof AI（AI受入テスト・導入確認支援システム）
- 宣伝文句：「うちの会社で使える？」を、資料の診断から改修依頼・テストまで支援。

## 2. 利用者
社内SE、情報システム部門の導入担当者、ITコンサルタント、利用部門の担当者（専門知識がなくても操作できること）

## 3. 業務の流れと画面
| 手順 | 画面 |
|---|---|
| 案件・候補製品の登録 | 案件・製品 |
| 製品資料・営業説明録画の登録、読込内容・文字起こし・話者・分析対象の確認 | 1 製品の資料・営業説明 |
| 自社の業務ルール・作業手順・必須条件の登録・確定 | 2 自社の仕事・ルール |
| AIの照合（下書き）と、人による根拠・診断の確認 | 3 自社に合うかを確認 |
| 質問・回答、対応方法、改修・設定変更等の依頼書 | 4 質問・対応依頼 |
| テストの確定、実機での実施・結果記録・再テスト | 5 試すこと・実施結果 |
| 残件と根拠の確認、人の導入判断 | 6 残った問題と導入判断 |
| JSON保存・再開、Excel出力 | 保存・Excel出力 |

## 4. 役割分担
- AI：要件の分割候補、関連箇所の照合と診断候補、質問・対応案、依頼書とテストのたたき台（すべて下書き）
- プログラム：読込と参照位置、音声抽出・文字起こし制御、ID・版・状態・関連付け、引用の実在検証、集計・保存・出力、古い根拠に基づく結果の検出、利用回数と費用の管理
- 人：要件・話者・発言内容・診断・回答・対応・依頼・テスト・期待結果の確定、実機テスト、導入判断

## 5. 機能要件（第1版で実装したもの）
1. 資料読込：PDF（文字あり）・.docx・.xlsx・.pptx・.txt・貼り付け。旧形式（.doc/.xls/.ppt）は変換を案内
2. 参照位置：PDF＝ファイル上のページと段落、Word＝見出し・段落番号（表は表番号・行）、Excel＝シート・セル範囲、PowerPoint＝スライド番号・タイトル・図形番号（グループ内）・表の行、テキスト＝行番号、貼り付け＝段落番号
3. PowerPoint：タイトル・テキストボックス・表・グループ内図形（再帰）・発表者ノート（初期状態で対象外、内容確認後のみ選択可）、非表示スライドの判別、画像・グラフ・SmartArt・コネクタを「理解していない要素」として警告
4. 読込確認：空・文字化け・読込失敗・表の崩れ・一部省略（上限）を表示。スライド・ページ・シート単位で対象選択と補足（原文と分離）
5. 録画：MP4/WebM/MOV の音声トラック・コーデック検証、処理前の確認表示、時間範囲指定、ローカル文字起こし、二重実行防止、同一録画の再利用、代替入力（VTT/SRT/時刻付き文章）
6. 発言管理：原文と修正文の分離、修正履歴、話者（役割・氏名・確認状態）は人が分類、発言の種類（質問・回答・条件付き・将来予定・未回答等）と自動の候補提示、数値・否定表現の確認フラグ
7. 営業発言のエビデンス化：録画名／開催日／開始～終了時刻／話者・確認状態／引用を表示。未確認は確定回答として扱わない。前後の発言を表示。書面確認の質問を定型で作成
8. 要件：手動登録・AI分割（下書き）、元文の数値・条件語の欠落警告、確定・版管理・廃止・履歴
9. 診断：6区分、満たす条件と残る条件、根拠の検証（ID・版・位置・引用の実在・選択状態・製品との関係）、根拠なしの断定の自動格下げ、人の確認、旧診断の保持
10. 質問・回答：状態管理、送付の記録（自動送信なし）、回答元（手動・資料・確認済み営業発言）、回答確認後の診断更新候補、質問書Excel
11. 対応方法：9種類の候補、人が採用・不採用を理由付きで判断
12. 依頼書：資料診断段階／テストで発生した現象の区別、全項目の編集、版管理、9状態の遷移ルール、相手の回答（不明な費用・工数は未回答のまま）、相手の完了と人の確認の区別、残件付き完了・見送りの理由、依頼書Excel（1件ずつ）、受入条件からテスト候補（AIなし）
13. テスト：観点・項目の管理、期待結果の確定、実施記録（実施不能は合否に数えない）、再テストは新しい履歴、旧版テストの結果は流用しない、不合格から依頼書
14. 状況一覧・導入判断：区分別件数、必須要件の未解決（資料上／実機の2種類）、未回答、未確定依頼、未実施、不合格、再確認、対応中。分母付きの率。人の判断（未判断・導入可・条件付き導入可・導入延期）と判断後の更新検出
15. 保存・出力：JSON（形式の版、関連・版・履歴・時刻を保持。バイナリなし。未選択ノートは既定で本文を保存しない）、レポート・質問書・依頼書の Excel
16. デモ：特徴の異なる3件（架空・無料）、初期状態へ戻す
17. 利用制限：上限値・予算・回数を設定で変更可能、実行前の見積表示、永続記録がない環境では有料処理を停止

## 6. 非機能要件
- APIキーなしでデモと手動機能が使えること
- 利用者ごとに編集を分離（Streamlit のセッション単位）
- 読込失敗・AI障害で入力中の作業を失わないこと
- HTML表示のエスケープ、Excel数式注入対策、マクロ・埋め込み・外部リンクを実行しない、ZIP展開後サイズの上限
- 一般的なノートPC（1366×768 程度）で主要操作が見えること

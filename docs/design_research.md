## 2. 参考にした点と ReadyProof AI での採用方法

| 観点 | 参考にした点 | 採用方法 |
|---|---|---|
| 配色・コントラスト | 法人向け・品質保証系は紺系＋白で落ち着いた印象（SHIFT・Quomiru・デジタル庁） | 主色 #1F4E8C（白背景とのコントラスト比 7:1 以上）、文字 #1A2433。状態ラベルは文字色と背景色を 4.5:1 以上の組み合わせに限定 |
| 文字サイズ・階層 | 大見出し→節→小見出しの段階的な絞り込み（Quomiru） | 作業画面は「画面名（subheader）→太字の小見出し→本文・注記」の3段に限定。大型の見出しはトップページだけ |
| 余白・情報密度 | 紹介ページは余白が多い。業務アプリ（Backlog）は一覧が中心 | トップは紹介ページ型、作業画面は「左：一覧／右：詳細」の高密度レイアウト。大型カードを使わない |
| ナビゲーション | パンくず・ページ内目次（SHIFT）、製品内の3項目タブ（Quomiru） | サイドバーに作業順（1〜6）の画面。各画面の上部に「案件・製品・プラン・現在の作業位置」を常時表示 |
| ボタンの優先順位 | 塗り／枠線／テキストの3段階（デジタル庁）。主要CTAは1つに絞る（各社） | 1つの操作領域で塗りボタン（primary）は1つ。確定・記録などの主操作のみ primary |
| 一覧・詳細・比較 | 対応関係の表（Quomiru）、状態の列（Backlog・Qase） | 要件・質問・依頼・テストは行選択で詳細を開く。診断区分は区分別件数で比較（総合点数は出さない） |
| 状態・進捗 | 結果区分（Passed/Failed/Blocked/Retest）、完了率（Qase）、4ステップの流れ（SHIFT） | 合格／不合格／実施不能／未実施を分け、実施不能は合否の分母に入れない。率は必ず「分子/分母」で表示。トップに6段階の流れ |
| 専門性・信頼感 | 算出条件の注釈（Backlog）、定義の脚注（Quomiru） | 集計の分母、根拠の検証範囲（引用の実在≠意味の妥当性）、AI下書き／人の確認済み／準備済みデモ結果を常に明示 |

ロゴ・画像・文章・独自図版はコピーしていない（色・構成の考え方のみ参考）。

## 3. 実装上の方針

- Streamlit 標準部品と公式テーマ（`.streamlit/config.toml`）を優先。CSS は `readyproof/ui/theme.py` に集約し、Streamlit 内部のクラス名には依存しない（自前クラスのみ）
- アイコンは Streamlit の Material アイコン（`:material/...:`）。絵文字・記号フォントに依存しない
- 状態は「色＋文字」。人の確認済みは実線枠、AI下書き・未確認は破線枠で区別
- 資料・発言など利用者由来の文字を HTML で表示する箇所は必ずエスケープ

## 4. 実画面の確認（2026-11-04）

Chrome（ヘッドレス・1366×860）で以下を確認した：トップページ、デモ1の診断・テスト・導入判断・資料登録、デモ3の発言確認・診断の根拠表示・質問。日本語表示、Material アイコン、状態ラベル、表の行選択が表示されることを確認した。

未確認：スマートフォン幅、Edge・Firefox・Safari、キーボードだけでの全操作（フォーカス表示は Streamlit 標準のものを変更していない）、スクリーンリーダー、ダークモード（テーマを light に固定）。

## 5. 画面の作り直し（2026-11-04・利用者の指摘を受けて）

指摘：上の余白が多い、アプリ名が目立たない、情報にメリハリがない、色がバラバラ、横並びの枠の下端がそろっていない、トップページが長い。

追加で参考にしたもの：
- Nielsen Norman Group「Visual Hierarchy in UX」 https://www.nngroup.com/articles/visual-hierarchy-ux-definition/ ：色は主要2色＋補助2色程度に絞る、赤は警告・エラーに限る、文字サイズは大中小の3段階、関連する要素は近づけて罫線や背景を多用しない
- IBM Carbon Design System「Status indicators」 https://carbondesignsystem.com/patterns/status-indicator-pattern/ ：赤＝危険、橙・黄＝警告、緑＝成功、青＝進行中、灰＝下書き・未着手、紫＝例外。色だけでなく文字・形と併用。対応が不要な情報は色を付けず文字で示す

採用したこと：
- 色の役割を固定：紺＝ブランド・主操作、緑＝OK・見込みあり、橙＝注意・追加対応、赤＝不可・不合格、紫＝根拠の矛盾、灰＝未確認・不明・補足、青＝進行中のみ
- 状態は Streamlit 標準のバッジ（色＋文字＋アイコン）。作成元や種類などの補足は色を付けない灰色の文字
- 文字サイズは「画面名／小見出し／本文」の3段階。日本語フォントを Noto Sans JP に統一
- 上の余白を詰め、サイドバー最上部にロゴ（全画面でアプリ名を表示）
- 横並びの数値枠・カードは CSS グリッドで高さと数値の位置をそろえる
- トップページは「何をするアプリか（見出し帯＋3項目）」「ガイド付きデモ」「自分の案件で使う」の3部構成に短縮
- ガイド付きデモ：各デモ5ステップ（約4分）。「次へ」で該当画面・該当項目へ自動で移動し、見どころを画面上部に表示

## 6. 画面の作り直し（ゼロベース・2026-11-04）

指摘：画面・タブ・ボタンが多く、何をするアプリか分かりにくい。利用者が気にするのは「入力1＝製品の資料・録画」「入力2＝自社のルール」「出力1＝そのまま使えるかの診断」「出力2＝受入テスト」だけ。

対応：
- 画面を4段階（① 製品の資料 → ② 自社のルール → ③ 診断結果 → ④ 受入テスト）に再構成し、上部に常に進み具合を表示（現在＝紺、入力済み＝空色の線）
- 画面内のタブを廃止し、上から下へ「入れる → 確かめる → 次へ」の一方向にした。詳細は「詳しく確認する」を押した1件だけ開く
- 質問・回答・対応方法・依頼書は ③ の要件ごとに、テストの実施記録・残件・導入判断は ④ にまとめた
- 入力2で聞くことを5つに絞った（業務の種類／必ず守るルール／例外・未定／誰が使うか・権限／使うときの条件）
- 受入テスト仕様書（Excel）を独立した成果物として出力（結果の記入欄つき）

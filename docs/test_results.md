## 2-2. Claude API の実呼び出し（2026-11-04 実施・利用者承認済み）

実行：`scripts/live_api_check.py`（3件のデモから準備済みの診断を外し、実際の Claude API で診断し直す）
モデル：claude-opus-5-5／呼び出し3回／費用 約35円（アプリの利用記録上の値。請求額は Anthropic コンソールで確認）
詳細：`docs/live_api_results.json`

| デモ | 所要時間 | 一致 | 内容 |
|---|---|---|---|
| デモ1 | 26.4秒 | 1/2 | REQ-002（自己承認禁止）は期待どおり「情報不足」。REQ-001 はAIが「設定で対応見込み」としつつ境界値（10,000円ちょうど）等を残る条件に挙げたため、プログラムの安全装置が「情報不足」に格下げ |
| デモ2 | 36.4秒 | 2/4 | REQ-002「追加対応」、REQ-003「対応不可の記載あり」は一致。REQ-001・REQ-004 はAIが資料に書かれていない条件（複数ロット時の全件表示、標準機能のみでの訂正者記録）を指摘して「情報不足」 |
| デモ3 | 20.1秒 | 2/2 | 資料と営業説明の矛盾、保存期間の未回答を正しく判定 |

**合計 5/8 一致。** 不一致3件はすべて「慎重側」（期待より弱い区分）で、「できないのにできる」とする誤りはなかった。AIが示した引用は25件すべて実在を確認でき、創作された引用（除外）は0件。

考察：期待区分（デモの準備済み結果）は、人が「テストで確認すればよい」と判断した条件を残る条件に含めていない。AIは同じ点を未確認の条件として挙げるため、安全装置で「情報不足」になる。今後の改善候補：「残る条件」を「資料で未確認（ベンダー確認が必要）」と「実機テストで確認すること」に分け、後者だけなら見込み区分を維持する（`docs/backlog.md`）。

注意：1回の実行・8件のみの結果で、精度の統計的な評価ではない。

追記（2026-11-04）：上の考察を BL-002 として実装し、デモのAI出力を作り直した（約99円）。デモ1の「10,000円ちょうどの扱い」などは「実機テストで確認すること」に分かれた。ただしデモ1の REQ-001 は、部長の割当方法などベンダー確認が必要な条件も残るため、区分は「情報不足」のまま（安全装置どおり）。

## 2-2-2. AIの聞き取り（BL-001 案B）の実呼び出し（2026-11-04）

実行：デモ1の入力（要件を空にした状態）で、質問づくり→回答（架空）→要件の下書き化を1回ずつ。費用は2回で約13円（実測）。

| 確認したこと | 結果 |
|---|---|
| 製品資料を踏まえた質問になるか | 8問。各質問の「なぜ聞くか」に資料の位置（スライド2の金額別承認ルート、スライド3の7年保存など）が入った |
| 製品の機能に誘導しないか | 自社の値を聞く形（境目の金額、ちょうどの金額の扱い、保存年数など）。資料にない点は「ベンダー確認の要否を判断するため」と明記 |
| 「分からない・未定」を推測で埋めないか | 2問を「分からない・未定」にした結果、要件の未確定事項に「未定：（質問）」として残った |
| 不自然な回答を勝手に直さないか | 確認用に年数・人数にも 10000 を入れたところ、「不自然。再確認が必要」と未確定事項に書き、値を補わなかった |

改善：数値の回答に単位がないため、AIが「金額の単位が回答にない」と未確定にした。質問に単位（円・人・年など）を持たせ、回答欄と聞き取りの記録に単位を付けるよう修正した。

修正後の実呼び出し（2026-11-05、2回で約13円）：回答が「10000円」「10000人」「10000年」と単位付きで渡り、「金額の単位が回答にない」という未確定事項は出なくなった。単位があることで、AIは「10000人の承認」「10000年の保存」を不自然と判断し、再確認事項にした（値は補わなかった）。

## 4. 既知の問題・制限

- 録画本体はセッションのメモリにのみ保持。ブラウザの再読込・画面URLの直接入力で新しいセッションになり、未保存の作業と動画は消える（JSON で保存して再開）
- 話者分離（誰が話したかの自動判定）はない。人がラベルごと・発言ごとに指定する
- 検索は文字の一致のため、言い換え・同義語は見つからないことがある（見つからない≠機能なし と表示）
- PDF の表は文字として抽出され、列の対応が崩れることがある
- 「プラン・オプション」等の注意表示はキーワードで出すため、表の見出し（例：「標準/オプション」）でも出ることがある
- アップロード上限の表示（Streamlit 標準の「200MB per file」）とアプリの資料上限（20MB）が異なる。アプリ側の上限で拒否する

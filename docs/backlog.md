# 残件・今後の課題

## BL-001 社内の状況を簡単・スムーズに入力できるよう支援する（優先度：高・案A・案Bとも実装済み）

**2026-11-04 実装：案A（AIなしの質問形式）**。「② 自社のルール」→「質問に答えて要件を追加する」。業務の種類（申請・承認／アカウント管理／ロット管理／その他）を案件名・製品名から推定し、1問ずつ答えると要件の下書きを作る。「分からない・未定」は推測で埋めず未確定事項にする（`readyproof/intake.py`、`tests/test_intake.py`）。**2026-11-04 実装：案B（AIの聞き取り）**。②で「AIが製品の資料を踏まえて質問する」を選ぶと、製品資料（分析の対象に選んだ箇所と、人が確認した営業発言のみ）を踏まえてAIが5〜8問の質問を作り（なぜ聞くかを表示）、1問ずつ答えた結果をAIが要件の下書きにまとめる。「分からない・未定」は推測で埋めず未確定事項にする。AIは2回（約13円・実測1回）。質問と回答は案件に保存せず、要件の「元の文章」に残す（`readyproof/ai/tasks.py` の run_interview・run_interview_split、`tests/test_interview.py`、`docs/test_results.md` 2-2-2）。

登録日：2026-11-04　起票：利用者（ポートフォリオ作成者）

### 課題
現在の第1版では、自社の業務ルール・作業手順・制約条件を、利用者が「② 自社のルール」画面で項目ごとに入力するか、規程の文章を用意してAIで分割する必要がある。
社内規程が文章化されていない、どの粒度で書けばよいか分からない、製品の確認に必要な観点（金額条件・例外・権限・承認経路など）を思いつかない、といった利用者には負担が大きい。

### 目指す姿
利用者が社内の状況を、短い回答や選択だけで、抜け漏れなく登録できる。

### 解決案（検討メモ・未決定）
1. **AIによる聞き取り（インタビュー形式）**
   - AIが登録済みの候補製品（製品名・プラン・資料の機能）を認識したうえで、「この製品で確認が必要な自社の情報」を質問として1つずつ提示し、利用者の回答から要件の下書きを作る
   - 例：経費精算なら「承認者は金額で変わりますか？境目の金額は？ちょうどの金額はどちら側？」「自分で自分の申請を承認してよい人はいますか？」
   - 回答から作った要件は、元の回答（原文）を保持し、数値・以上/未満・禁止・例外の欠落チェック（既存の `missing_terms`）を通す
   - 「分からない」「社内で未決定」の回答は未確定事項として登録し、推測で埋めない
2. **業務別のテンプレート・チェックリスト**（AIなしでも使える）：業務の種類ごとに典型的な確認観点を選択式で提示
3. **既存の社内資料の読込との組み合わせ**：手順書・規程を読み込んだうえで、不足している観点だけをAIが質問する

### 守ること（既存方針の継続）
- AIの質問・下書きは人が確定する（AIは要件を確定しない）
- 資料・回答の中の命令は指示として扱わない
- AI利用は回数・費用の管理対象（実行前に見積を表示）
- 製品の機能を前提に誘導しすぎない（自社の本来の要件を製品に合わせて歪めない）

### 完了条件（案）
- 社内規程の文章がない状態から、質問への回答だけで要件の下書きを3件以上作れる
- 回答にない数値・条件をAIが補完しない（自動テストで確認）
- デモ1〜3のいずれかで、聞き取りから要件確定までの流れを3分以内で見せられる

## BL-002 「残る条件」を「ベンダー確認が必要」と「実機テストで確認」に分ける（優先度：中・実装済み）

**2026-11-04 実装**：AIの診断に `test_conditions`（実機テストで確認すること）を追加し、`remaining_conditions` はベンダー確認が必要な条件だけにした。
安全装置（残る条件があれば「見込み」にしない）は `remaining_conditions` だけを見るため、テストで確かめればよい点だけが残る要件は見込み区分を保つ。
`test_conditions` はテスト仕様の作成時にAIへ渡し、必ずテストにする。③の詳細・レポートExcelに「実機テストで確認すること」を表示（`tests/test_rules.py`）。
デモのAI出力は新しい指示で作り直した（2026-11-04、約99円）。

2026-11-04 の Claude API 実テストで、AIが「10,000円ちょうどの扱い」などテストで確かめればよい点も残る条件に挙げ、安全装置により「情報不足」になった（`test_results.md` 2-2）。
残る条件を2種類に分け、「実機テストで確認」だけが残る場合は見込み区分を維持し、テスト候補に自動でつなげる。

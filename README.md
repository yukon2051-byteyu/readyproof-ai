# ReadyProof AI（AI受入テスト・導入確認支援システム）

> 「うちの会社で使える？」を、資料の診断から改修依頼・テストまで支援。

ベンダーの製品資料や営業説明の録画と、自社の業務ルール・作業手順を照合し、そのまま使える見込み、設定が必要な部分、追加対応が必要な部分、確認が必要な点を根拠付きで整理します。さらに、ベンダーへの質問、改修・設定変更依頼書、受入テストの作成と結果管理まで支援します。

## 解決する業務課題

SaaS やパッケージの導入検討では、次のことがよく起こります。
- 提案書の「対応可能」や営業の口頭説明を、そのまま「自社で使える」と受け取ってしまう
- 上位プラン限定・オプション・将来予定などの条件が、比較表や議事録から抜け落ちる
- 導入後の受入テストで、どの要件をどの根拠で確認したのかが追えない

ReadyProof AI は、**「資料や営業説明から分かる見込み」と「実機で確認できたこと」を分けて**管理し、根拠（資料のページ・スライド、発言の時刻と話者）を最後まで追えるようにします。

- 対象：社内SE、情報システム部門の導入担当者、ITコンサルタント、利用部門の担当者
- 既存作品との違い：AI-BIC（業務課題と改善案の整理）、ChangeScope AI（変更による組織・システムへの影響整理）とは異なり、本作品は「候補製品が自社業務に合うか」「不足をどう埋めるか」「実際に要件を満たしたか」に集中しています（連携は第1版では対象外）

## 主な機能

1. **製品の資料・営業説明**：PDF（文字あり）/ Word / Excel / PowerPoint / テキスト / 貼り付け。位置（ページ・見出しと段落・シートとセル範囲・スライドと図形・行）付きで抽出し、読めなかった部分・警告を表示。スライド別に対象選択・ノート確認・補足
2. **録画**：MP4 / WebM / MOV の音声を検証し、時間範囲を指定してローカルで文字起こし。話者・内容は人が確認・修正（原文は残る）。会議ツールの VTT / SRT / 時刻付き文章も読込可
3. **自社の仕事・ルール**：手動登録・AI分割（下書き）。元文の金額・以上/未満・禁止が落ちていないかを警告。確定・版管理
4. **自社に合うかを確認**：6区分の診断と根拠。引用の実在・位置・選択状態・製品の一致をプログラムで検証。根拠なしの断定は自動で「情報不足」へ
5. **質問・対応依頼**：質問書 Excel、回答の記録と確認、対応方法の判断、依頼書（版・状態・相手の回答・人の完了確認）と依頼書 Excel
6. **試すこと・実施結果**：テストの確定、実機での結果記録、再テスト履歴、不合格から依頼書
7. **残った問題と導入判断**：区分別件数と分母付きの率、残件一覧、人の判断（判断後の更新を検出）
8. **保存・出力**：JSON で保存・再開、適合性・導入確認レポート Excel

## 対応形式と読める範囲（制限）

- PowerPoint：タイトル・テキストボックス・表（行単位）・グループ内の図形・発表者ノート（初期状態で対象外）。**画像内の文字、矢印・図形の位置関係、グラフ、SmartArt、アニメーションは理解しません**（警告を表示）。同じスライドに「金額」と「承認者」があるだけで金額別承認と判断しません
- PDF：文字情報を含むもののみ（OCR なし）。表は列が崩れることがあります
- Word：本文・見出し・表。ヘッダー/フッター・テキストボックス・コメントは対象外
- Excel：保存済みの値を読みます（数式は計算しません）。非表示シートは初期状態で対象外
- 旧形式（.doc / .xls / .ppt）は新形式または PDF への変換を案内します
- 録画：音声の発言内容のみ（映像・画面共有の内容は対象外）。**話者の自動判定はありません**。動画本体は JSON に保存されません

## 話者と発言の確認方法

1. 「1 製品の資料・営業説明」→「発言の確認」で、自動ラベル（例：話者1）ごとに役割（営業担当者・自社担当者など）と氏名を設定し「確認済み」にする
2. 発言ごとに文章を修正（原文は残り、履歴が付く）し、種類（質問・回答（条件付き）・将来予定・未回答・調査中 など）を選び、内容確認を「確認済み」にする
3. 数値・金額・否定表現・製品名に注意フラグが付きます。聞き取れない箇所は創作せず「聞き取り不能」とします
4. 確認済みのベンダー発言だけが「確定した営業回答」として扱われます。未確認の発言は根拠に使えますが、警告が付きます

## 根拠検証の限界

プログラムが確認するのは「引用がその資料・発言に実在するか」「その箇所が分析対象か」「対象製品の資料・録画か」「確認済みか」までです。**引用が要件を満たす意味かどうか（妥当性）は人が確認します。** 検索で見つからないことは、機能がないことを意味しません。

## 起動方法（Windows）

```powershell
# 初回のみ：Python 3.12 の仮想環境を作り、ライブラリを入れる
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -r requirements-dev.txt

# 起動（ブラウザが開きます）
.venv\Scripts\streamlit run app.py
```

- API キーがなくても、デモ・手動入力・AIを使わない検索・Excel/JSON 出力・ローカル文字起こしが使えます
- ローカル文字起こしは `requirements-local.txt`（`requirements-dev.txt` に含む）で入ります。初回にモデル（small・約480MB）を自動ダウンロードします。公開サイトには入れていません（重いため。録画は会議ツールの文字起こし読込で使います）
- **ブラウザを再読込すると未保存の作業は消えます。** 「保存・Excel出力」から JSON で保存してください

## 設定（AI を使う場合・費用）

`.streamlit/secrets.toml`（Git に入れない）または環境変数で設定します。

```toml
ANTHROPIC_API_KEY = "（自分のキー）"
RP_ACCESS_CODES = "code-a,code-b"          # 利用コード（共有すると回数枠も共有）
RP_USAGE_STORE_PERSISTENT = "true"         # 利用記録の保存先が永続的な場合のみ true
RP_USAGE_LEDGER_PATH = "data/usage_ledger.jsonl"
```

- 初期値：月のアプリ予算 6,000円、AI生成は1コードにつき月3回（再生成も1回）、診断は1回最大10要件、テスト生成は最大15件、依頼書は1件。上限はすべて `RP_` で始まる環境変数で変更できます（一覧は「設定・利用枠」画面）
- 実行前に送信先・送信内容・費用見込み（出力上限まで使い再試行1回を含む最大額）を表示します
- 永続的な利用記録の保存先がない環境では、有料処理を停止します
- アプリ予算は請求額の保証ではありません。Anthropic コンソール側の支出上限も設定してください
- モデルは `claude-opus-5-5`（設定 `RP_MODEL` で変更可）。料金単価も設定値です（公式価格表で確認してください）

## デザイン方針

品質保証・テスト管理・法人向け業務アプリの公式サイト（SHIFT、Quomiru、Backlog、Qase、デジタル庁デザインシステム）を調査し、紺系の配色、作業順のナビゲーション、一覧と詳細の2列構成、色＋文字の状態表示、分母付きの集計を採用しました。詳細は [docs/design_research.md](docs/design_research.md)。

## データの取り扱い

- 公開環境では、外部送信が許可された資料・録画、または匿名化した情報だけを使ってください。録画は参加者の利用許可を確認してから登録してください
- アップロード（アプリ内）／音声処理（サーバー内・外部送信なし）／文字の AI 送信（Claude API）は別の操作で、AI 送信の前に送信先と内容を表示します
- 資料・発言の中の命令はアプリへの指示として扱いません。マクロ・埋め込み・外部リンクは実行しません
- 認証はありません。作業者名は自己申告で、本人確認や正式な承認ではありません
- サンプルの会社・製品・人物・資料・録画はすべて架空です
